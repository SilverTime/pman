# pman Next：GLM 5.3 开发交接与验收清单

本文是后续实现的产品契约。目标是完成 Windows 上的个人 AI 连接与授权中心：用户保存或登录一个账号，选择 AI 工具，持续使用该连接；失效时知道原因并能恢复。不要重新发散视觉方向，不要用占位按钮、模拟成功或仅前端状态完成任务。

## 0. 执行约定

1. 阅读根目录 AGENTS.md、本文、IMPLEMENTATION.md、三张概念图以及当前代码，再开始修改。
2. 按下面依赖顺序完成任务；每项记录实际变更文件、验证命令与结果。只有通过对应验收才能勾选。无法验证时明确标为未验收，不能计入完成率。
3. 所有开发测试使用临时合成数据和隔离存储，禁止读取用户真实保险库、密钥文件或浏览器凭据。真人登录必须在产品登录窗口中由用户完成，不让凭据进入模型上下文。
4. 保留现有 E10、CLI、MCP、配对、管理锁、备份恢复及细粒度策略。不要重写整个技术栈，不要新增与本目标无关的服务端。
5. 不擅自安装覆盖现有版本、发布安装包或操作真实授权。开发实现这些功能不等于获准对用户真实数据执行这些操作。
6. 发现本文与第三方实际能力不一致时，记录证据和最小调整方案；保持产品目标，不伪造第三方支持。安全边界冲突时先停下相关实现，不绕过。

## 1. 已确定且不得回退的产品方向

- 产品主体是“连接”，不是凭据字段管理器。一个连接对应一个服务下的一个账号/环境；同服务多个账号独立显示、独立授权。
- 默认路径：添加连接 → 登录或录入 → 选择 AI → 授权并检查 → 返回详情。
- 授权默认是整条连接、持续到撤销。HTTP 路径、方法、时间、参数等限制保留在高级设置，不能变成首次接入必填项。
- 持续授权不是复用一次性审批 ID；必须落入可撤销的策略。明确拒绝及既有更严格限制不能被悄悄删除。
- “管理界面已锁定”与“AI 服务已暂停”是两个状态。关窗口、管理锁、Windows 锁屏和闲置不应自行停止已授权 API 调用；显式暂停才停止。新登录、改授权等管理操作仍需管理解锁。
- 普通密码只供本人保管，不向 AI 开放；AI 只通过连接别名与授权代理使用其他凭据。
- API 使用和网页操作是独立能力。已有 API 授权不得自动扩展成网页操作授权。
- 已保存、身份已验证、授权已保存、本机代理检查通过、真实 AI 调用成功是不同证据，不得用一个“已连接”覆盖全部。

### T02 — 完整的 API 接入、检查与恢复（P0）

- [ ] 新增明确的“检查连接”原生操作，通过既有代理/策略链验证，不直接从 React 请求第三方。UI 的连接检查与 AI 客户端检查分开。
- [ ] GitHub/GitLab 使用官方只读身份接口验证，解析最少身份信息；实现前查官方文档并记录 URL、日期、适用版本。通用 API 允许用户配置只读检查路径，未知服务没有检查路径时只报告保存状态。
- [ ] 检查不通过写请求测试权限；403 不一概当作凭据过期；网络失败不删除凭据。结果标注作用域与时间，不能证明所有业务接口均可用。
- [ ] 登录/更新凭据后重新检查；刷新失败提供重试/重新登录。不能自动重放用户业务写请求。
- [ ] 授权后并列显示“授权已保存”和“本机检查结果”；检查失败保留已经成功保存的授权，避免用户反复授权。
- [ ] 覆盖规则冲突：整连接授权与旧 require_approval/deny 并存时显示仍有限制，不宣称无条件免审批。撤销后下一次请求立即重新鉴权。

验收：合成服务返回 200/401/403/429/超时，UI 与恢复动作分别正确；检查没有 POST/PUT/DELETE 业务副作用；更换账号或地址后旧检查结果失效；撤销后使用同一客户端身份再次请求被拒绝。

代码入口：pman-core/src/http_proxy.rs、policy.rs、workspace.rs；desktop/src-tauri/src/backend.rs；ConnectionLibrary.tsx、Access.tsx。

### T03 — GitHub / GitLab OAuth 与可扩展提供方（P1）

- [ ] 先写 OAUTH-PROVIDERS.md：逐个确认 GitHub、GitLab.com、自托管 GitLab 支持的授权流程、PKCE/回调限制、应用注册责任、scope、刷新/撤销能力及官方资料。不能假定两个提供方支持相同流程。
- [ ] 采用提供方正式支持的原生应用流程；优先无需内置 client secret 的方案。需要机密客户端的流程不得把 secret 打包进桌面或让模型收集它，缺少部署条件则保留明确可用的 Token 路径。
- [ ] 在现有登录隔离架构内建立提供方适配接口：begin/complete/cancel/status；原生端完成交换和保存，前端仅拿 flowId、expiresAt、状态和脱敏身份摘要。具体函数名可调整，语义不可省略。
- [ ] 一次性 state、PKCE（提供方支持时）、回调地址/来源校验、超时/取消、账号与环境绑定、重复回调拒绝必须实现。回调不可凭 alias 或显示名称绑定客户端。
- [ ] 流程绑定发起时的管理认证 epoch 与连接版本；锁定、删除、改地址、切账号后旧回调失效，不写入新账号。
- [ ] 支持令牌到期、受支持的刷新与重新登录；刷新单飞，持久化原子性，401 不无限重试，不自动重放写操作。
- [ ] 向导服务选择后清楚呈现真实可用的登录方式；OAuth 未配置时说明原因并提供 Token，不能展示假“连接成功”。
- [ ] 登录成功只完成账号接入，随后仍必须经过选择 AI 和授权步骤。

验收：本地模拟授权服务覆盖成功、拒绝、错误 state、过期、取消、重复回调、账号变更、刷新并发；最终由用户完成各提供方真实登录验证，无法执行的单列“未验收”。任何 token/code/secret 均不进入前端日志、URL 持久化、审计正文或 AI 响应。

代码入口：desktop/src-tauri/src/login.rs、service.rs；pman-core/src/e10.rs 可参考生命周期但不要硬编码成通用 OAuth；新增适配模块、协议类型及持久化迁移。

### T05 — AI 网页操作通道（P1，必须先交付权限设计）

- [ ] 在 BROWSER-CONTRACT.md 定义并实现独立 browser 能力授权、会话所有权、origin 范围、可用动作与错误。默认关闭，已有 API 授权不迁移为网页权限。
- [ ] 产品内从详情“网页操作”开启，明确展示账号、环境、AI、允许站点与能力；默认该连接持续到撤销，保留高级限制。
- [ ] 复用 pman 管理的隔离 WebView2 会话，不读取用户外部浏览器 Cookie 数据库，不使用注入用户日常浏览器的捷径。远程网页不能调用管理命令。
- [ ] 最小动作覆盖打开连接、获取可交互页面摘要、点击、填写普通字段、等待状态、关闭会话。经现有配对与策略通道暴露给 CLI/MCP，不能建立匿名调试端口。
- [ ] 页面快照和工具响应屏蔽密码、token、Cookie、认证请求头、敏感输入与浏览器存储；不得提供任意脚本执行、原始网络抓包或读取 localStorage 的旁路。
- [ ] 密码/验证码等认证步骤交给用户的隔离登录窗口；AI 看不到输入。不能仅依赖 HTML input type=password，需测试其他敏感字段和页面回显。
- [ ] 每次动作重新检查客户端、连接、授权及会话代次；导航和重定向限制到授权 origin，新站点需要用户新增范围，网页内容不能扩大权限。
- [ ] 文件上传下载、支付/删除/发布等敏感动作第一版禁用或采用明确确认机制；不能仅依据按钮文本可靠判定安全。若无法可靠实现边界，该类动作返回不支持，文档列明。
- [ ] 管理锁定时禁止新认证和管理弹窗；持续网页会话的执行边界需要在契约中明确，不得顺带中断已授权 API。显式暂停、撤销、删除连接时立即拒绝后续动作并关闭受影响会话。
- [ ] 活动页记录脱敏动作与结果、客户端及连接；提供停止网页会话入口。只有端到端通过后，详情才将“尚未接入”变为可用。

验收：用本地合成网站完成登录后读表单、填写非敏感字段和普通导航；跨 origin、伪造会话 ID、撤销后旧会话、恶意页面要求读取凭据、敏感字段快照、任意脚本请求全部拒绝或脱敏。原生登录窗口不能调用管理 API。真实网站验收单独记录，不以模拟测试替代。
